# Structural parser round

This round targets work that repeats across table rows, table-cell source
remapping, references, and nested list reparsing. The accepted fork already
contains fused reference/footnote prepasses, cached balanced-link probes,
arena-backed list sources, and direct table-row construction, so those paths
are treated as controls rather than new hypotheses.

## Ranked hypotheses

1. **Compact table-cell source remapping (selected).** `unescape_table_pipes`
   currently allocates one `u32` source boundary for every generated byte in a
   cell whenever one escaped pipe exists. A long cell with one `\\|` therefore
   pays O(bytes) metadata and a second metadata write loop, although only a few
   boundaries differ from identity. Store the generated positions of removed
   backslashes instead and map boundaries with a lower-bound count. Prediction:
   escaped-pipe tables with long prose cells should reduce arena bytes and
   parser-side metadata work; heavily formatted cells may trade a little span
   remap CPU for that memory reduction. Plain cells remain unchanged.

2. **Fuse table splitting and escaped-pipe discovery.** Row splitting checks
   every pipe's backslash parity, then each cell scans its contents again to
   find escaped pipes before unescaping. Carrying escaped-pipe positions from
   the row splitter could remove that second search. Prediction: dense tables
   with many escaped pipes improve, while ordinary tables see little change.
   This is deferred because the current iterator API makes ownership and cell
   trimming interactions easy to get wrong, and the compact map addresses the
   dominant allocation more locally.

3. **Reference prepass line metadata.** Cache line starts or candidate windows
   for the fused definition/footnote prepass to avoid repeated `line_end` and
   quote stripping. Prediction: definition-heavy documents improve, but the
   existing shared definition-region cache and fence skip already cover the
   known quadratic cases; extra metadata would cost every root parse.

4. **Nested-list source-map run representation.** Replace per-line source-map
   entries with a compact run structure for list item reparsing. Prediction:
   deeply nested multiline lists reduce metadata allocation, but every inline
   span remap path would become more complex and the current SourceMap already
   stores one entry per source line rather than per byte.

5. **Inline-link probe cache sharing across sub-parsers.** Share the existing
   cache with child parsers to avoid repeated probes in nested list/quote
   sources. Prediction: pathological nested links improve, but cache keys are
   source-slice addresses and child sources can be arena-generated; sharing
   would increase retained memory and complicate lifetime/reset behavior.

## Selected algorithm

For table cells containing escaped pipes, emit the unescaped cell into the
arena and record each removed backslash's position in the generated string.
The positions are strictly increasing and are sufficient to reconstruct any
generated boundary: `source_boundary = generated_boundary + count(removed_pos <
generated_boundary)`. Span remapping uses a lower-bound search over this sparse
vector. This preserves byte offsets exactly while reducing mapping storage from
O(cell bytes) to O(escaped pipes).

Expected workloads: long prose cells with one or a few `\\|` escapes; tables
with inline formatting and escaped pipes; ordinary tables without escapes;
short cells and dense escaped-pipe rows as controls. Correctness requires
byte-identical rendered output, AST snapshots, source spans, and all existing
table edge cases.
